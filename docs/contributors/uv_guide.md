# Работа с зависимостями через uv

## Введение

В проекте **OpenVair** управление зависимостями выполняется через инструмент [**uv**](https://docs.astral.sh/uv/).  
Он объединяет функционал `pip`, `venv`, `pip-tools`, `poetry/pdm` и обеспечивает единый современный процесс установки и
фиксации зависимостей.

Все зависимости фиксируются в двух файлах:

- **`pyproject.toml`** — декларативное описание зависимостей (основные и dev-группы).
- **`uv.lock`** — зафиксированные версии для детерминированной сборки окружения.

---

## Основные команды

```bash
# установка зависимостей по lock-файлу
uv sync

# пересборка lock-файла (без обновления пакетов)
uv lock

# добавление новой зависимости
uv add <package>

# добавление в dev-группу
uv add --group dev <package>

# обновление конкретного пакета
uv lock --upgrade-package <package>

# удаление пакета
uv remove <package>

# запуск команды в окружении
uv run pytest

# просмотр дерева зависимостей
uv tree
```

## Преимущества

- Детерминированность — одинаковая среда на всех машинах за счёт `uv.lock`.
- Скорость — кэш и быстрый резолвер зависимостей.
- Чистота — нет `requirements.txt` и `pip freeze`.
- Интеграция — запуск `pytest`, `alembic`, `pre-commit` через `uv run`.

## Типовые сценарии

1. Добавление новой зависимости
    ```bash
    uv add requests
    ```
   — попадёт в `[project].dependencies`.
   Если зависимость нужна только для разработки:
    ```bash
    uv add --group dev pytest
    ```
   — попадёт в `[dependency-groups].dev`.

2. Обновление пакета
    ```bash
    # пересобрать lock без обновления
    uv lock
    
    # обновить только sqlalchemy
    uv lock --upgrade-package sqlalchemy
    
    # обновить все пакеты
    uv lock --upgrade
    ```

3. Жёсткая фиксация версии
   В pyproject.toml можно указывать разные стратегии:
   ```toml
   sqlalchemy = "==2.0.32"      # ровно эта версия
   pydantic = "~=2.9.0"         # любые 2.9.x
   fastapi = ">=0.116,<0.117"   # диапазон
   ```

4. Удаление пакета
   ```bash
   uv remove pre-commit
   uv sync
   ```

5. Смена версии Python
   ```bash
   uv python install 3.12
   uv venv --python 3.12 --clear
   uv sync
   ```
   Lock-файл проверит совместимость с `requires-python`.

6. Диагностика зависимостей
   ```bash
   # дерево зависимостей
   uv tree
   
   # кто подтянул pydantic?
   uv tree pydantic
   
   # очистка кэша
   uv cache prune
   ```
   Для поиска "мусорных" зависимостей используется:
   ```bash
   uvx deptry .
   ```

## Работа в CI/CD

- Для CI всегда использовать:
   ```bash
   uv sync --frozen
   ```
  Это гарантирует, что `uv.lock` не изменится.
- В PR коммитить изменения сразу в двух файлах: `pyproject.tom`l и `uv.lock`.

## Отличия от старого подхода

| Было                            | Стало с uv |
|---------------------------------|------------|
| pip install -r requirements.txt | uv sync    |
| pip freeze                      | uv lock    |
| venv / virtualenv               | uv venv    |       
| pip install                     | uv add     |

## Рекомендации для команды

1. Всегда использовать `uv run …` для запуска (например, `uv run pytest`, `uv run alembic upgrade head`).

   > `uv run` безопаснее, чище и универсальнее, чем активация venv вручную. Он гарантирует, что команда выполнится: с
   > нужной
   > версией Python, в корректном виртуальном окружении, с зависимостями, зафиксированными в uv.lock, без побочных
   эффектов
   > и
   > лишних переменных окружения.
    <details>
    <summary>Более подробно</summary>

    - **uv сам находит и активирует окружение**

      Когда выполняется:
        ```bash
        uv run pytest
        ```
      `uv`:
        - автоматически определяет, где находится ближайший pyproject.toml и .venv,
            - активирует это окружение под капотом,
            - подставляет нужные PATH, PYTHONPATH и sys.path,
            - и выполняет команду в нужном контексте.

      Это избавляет от риска, что ты случайно находишься «не в том» окружении или забыл активировать venv.

      Пример:
        ```bash
        uv run alembic upgrade head # Всегда из нужного .venv
        ```
      в отличие от:
        ```bash
        source .venv/bin/activate
        alembic upgrade head # зависит от того, что сейчас в PATH
        ```

    - **uv run гарантирует чистое окружение**

      Если ты активируешь venv вручную (`source .venv/bin/activate`),
      текущее shell-окружение сохраняется — со всеми переменными, алиасами и PATH.
      Это может привести к трудноотлавливаемым багам, особенно при работе с systemd, CI или при переключении между
      проектами.

      `uv run` создаёт временное «чистое» окружение на время выполнения команды → результат предсказуемый.

    - **Совместимость с lock-файлом**

      `uv run` использует зависимости из `uv.lock`, а не просто из активного venv.
      Если пакет в окружении случайно не совпадает с lock-файлом (например, обновлён вручную), `uv` это заметит и
      предупредит. Это повышает детерминированность исполнения команд.

    - **Унификация в CI и systemd**

      `uv run` работает одинаково:
        - в интерактивной консоли;
        - внутри systemd сервисов;
        - в скриптах CI/CD;
        - в установочных bash-скриптах.

      То есть вместо разного поведения для разработчика и демона (`.venv/bin/python `vs активированный venv), всегда
      можно писать единообразно:
       ```bash
       uv run python openvair/main.py
       uv run pytest -q
       uv run alembic upgrade head
       ```

    - **Автоматическая установка недостающих пакетов**
      Если при выполнении `uv run` не хватает зависимостей (например, после клонирования проекта), `uv` предложит
      запустить
      uv sync и установить их автоматически. При обычном venv это нужно делать вручную.

    - **Совместимость с несколькими окружениями**
      Если в будущем появится разделение окружений (например, `openvair-core`, `openvair-ui`, `openvair-tests`),
      `uv run`
      будет сам выбирать правильный `pyproject.toml` и не нужно будет вручную переключать `.venv`.

    - **Лучше для скриптов и сервисов**
      Для `systemd` юнитов, установочных скриптов, `pre-commit` хуков и подобных сценариев `uv run` предпочтительнее,
      потому что не требует `source` (а `source` — это bash built-in, не совместимый с `/bin/sh`, `systemd`, `cron` и
      т.п.).

      Пример:
      ```bash
      ExecStart=/opt/aero/openvair/.venv/bin/python -u main.py # зависит от пути
      ExecStart=uv run python -u main.py # всегда найдёт окружение
      ```
    </details>

2. Для продакшена использовать lock-файл без изменений (`uv sync --frozen`).
3. Не редактировать `uv.lock` вручную.
4. Проверять зависимости при помощи:

```bash
uv tree
uvx deptry .
```

## FAQ

**Почему установилась не та версия пакета?**
— Проверь `pyproject.toml`. Если версия указана как `~=2.9`, то разрешены все `2.x` начиная с `2.9`. Используй `==` или
более жёсткий диапазон.

**Как пересобрать окружение с нуля?**

```bash
rm -rf .venv
uv sync
```

**Что делать, если пакет требует системные библиотеки?**
— Установить их через `apt` до запуска `uv sync` (например, `libpq-dev`, `libvirt-dev`).
