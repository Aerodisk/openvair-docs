# Тесты модуля volume

## Подход к тестированию

Тесты для модуля volume реализованы как **интеграционные** и покрывают полный
жизненный цикл объектов и их интеграцию с инфраструктурой (RabbitMQ, Postgres,
файловая система).  
Тесты нацелены на проверку работы публичных API, бизнес-логики, проверки
ограничений, работы с ошибками и обнаружения регрессий при изменениях.

---

## Цели тестирования

- Проверка всех публичных API-эндпоинтов модуля `volume`
- Поддержание корректности бизнес-логики, валидаций и ограничений
- Предотвращение регрессий при доработках модуля
- Документирование допустимых/недопустимых сценариев (для последующего
  обновления документации)
- Обеспечение устойчивого рефакторинга и внедрения новых фич

---

## Организация и инструменты

- `pytest` и `fastapi.testclient` — запуск тестов, взаимодействие с API
- Интеграция с реальной БД Postgres, RabbitMQ, файловой системой (`qemu-img`,
  `libvirt`)
- Все тесты используют фикстуры для быстрой инициализации storage, volume и
  других зависимостей
- Для генерации входных данных — Pydantic, uuid, sqlalchemy, time.sleep()
- Переменные среды настраиваются через `.env.test` и pydantic-settings
- После каждого теста производится очистка тестовых данных для гарантии
  изолированности

---

## Структура тестовых файлов

```
tests/
│
├── api/
│ ├── test_create.py # POST /volumes/create/
│ ├── test_delete.py # DELETE /volumes/{id}/
│ ├── test_edit.py # PUT /volumes/{id}/edit/
│ ├── test_extend.py # POST /volumes/{id}/extend/
│ ├── test_retrieve.py # GET /volumes/, /volumes/{id}/
│
├── conftest.py # Общие фикстуры и подготовка окружения
├── config.py # Pydantic-конфигурация тестовой среды
├── .env.test # Переменные среды (TEST_STORAGE_PATH и др.)
├── pytest.ini # Конфигурация порядка запуска, логирования
```

---

## Используемые фикстуры

- **test_storage**: создаёт и удаляет хранилище через API
- **test_volume**: создаёт и удаляет виртуальный том через API
- **attached_volume**: добавляет фиктивную привязку тома к ВМ в БД
- **mock_auth_dependency**: подмена реальной аутентификации JWT
- **cleanup_all_volumes**: удаление всех томов через доменную логику

---

## Покрытие тестами

| Эндпоинт                              | Назначение                            | Статус           |
|---------------------------------------|---------------------------------------|------------------|
| `POST /volumes/create/`               | Создание тома                         | ✅ покрыт         |
| `GET /volumes/`                       | Список томов с фильтрами и пагинацией | ✅ покрыт         |
| `GET /volumes/{volume_id}/`           | Получение тома по ID                  | ✅ покрыт         |
| `PUT /volumes/{volume_id}/edit/`      | Редактирование метаданных             | ✅ покрыт         |
| `POST /volumes/{volume_id}/extend/`   | Расширение размера                    | ✅ покрыт         |
| `DELETE /volumes/{volume_id}/`        | Удаление тома                         | ✅ покрыт         |
| `POST /volumes/{volume_id}/attach/`   | Привязка к VM                         | ⏳ не реализовано |
| `DELETE /volumes/{volume_id}/detach/` | Отвязка от VM                         | ⏳ не реализовано |

Покрываются как позитивные, так и негативные сценарии, ошибки валидации,
нарушения бизнес-правил, исключения RPC и инфраструктурные ошибки.

---

## Инфраструктурные детали

- Тесты используют реальные RabbitMQ и Postgres, а также файловую директорию (
  `/dev/vdb`)
- Для тестов создаётся storage с типом `localfs`, который каждый раз очищается
- Все тесты независимы, не зависят от порядка выполнения

---

## Запуск тестов

```bash
cd openvair/modules/volume/tests/
pytest -v
```

Можно дополнительно настраивать логирование и порядок выполнения тестов через
pytest.ini.
Рекомендуется использовать плагины для интеграции с IDE (VSCode, PyCharm) для
удобства запуска и анализа результатов.

## Примечания
- В текущей реализации тесты запускаются вручную после внесения изменений в код.
- В дальнейшем тесты можно встроить в CI/CD pipeline для автоматической проверки.
