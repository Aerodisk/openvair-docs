# Тесты модуля volume

## Цели тестирования

- Проверка всех публичных API-эндпоинтов модуля `volume`
- Обеспечение корректности бизнес-логики, валидаций и ограничений
- Выявление и предотвращение регрессий после изменений
- Документирование допустимого и ошибочного поведения
- Обеспечение устойчивого рефакторинга и внедрения новых фич

---

## Подход к тестированию

Тесты для volume реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- В тестах задействуются реальные RPC-вызовы (RabbitMQ), операции с БД (
  PostgreSQL), файловой системой (`qemu-img`, `libvirt`)
- Проверяются сценарии полного жизненного цикла: создание, изменение,
  расширение, удаление, получение, фильтрация, валидация, ошибки, исключения
- Тестируются как позитивные, так и негативные сценарии

---

## Организация и инструменты

- `pytest`, `fastapi.testclient` — запуск тестов, работа с API
- Реальная БД Postgres, RabbitMQ, файловая система (test storage)
- Конфигурация окружения: `.env.test` и pydantic-модели
- Очистка всех данных после тестов фикстурами для изоляции

---

## Структура файлов

```
tests/
│
├── api/
│   ├── test_create.py      # POST /volumes/create/
│   ├── test_delete.py      # DELETE /volumes/{id}/
│   ├── test_edit.py        # PUT /volumes/{id}/edit/
│   ├── test_extend.py      # POST /volumes/{id}/extend/
│   ├── test_retrieve.py    # GET /volumes/, /volumes/{id}/
│
├── conftest.py             # Общие фикстуры, подготовка окружения
├── config.py               # Pydantic-конфиг тестовой среды
├── .env.test               # Переменные среды для тестов
├── pytest.ini              # Порядок запуска, логирование
```

---

## Используемые фикстуры

- **test_storage**: создаёт и удаляет хранилище через API
- **test_volume**: создаёт и удаляет виртуальный том через API
- **attached_volume**: добавляет фиктивную привязку тома к ВМ в БД
- **mock_auth_dependency**: подмена реальной JWT-аутентификации
- **cleanup_all_volumes**: удаление всех томов через доменную логику

## Покрытие эндпоинтов

| Эндпоинт                              | Назначение                            | Статус           |
|---------------------------------------|---------------------------------------|------------------|
| `POST /volumes/create/`               | Создание тома                         | ✅ покрыт         |
| `GET /volumes/`                       | Список томов с фильтрами и пагинацией | ✅ покрыт         |
| `GET /volumes/{volume_id}/`           | Получение тома по ID                  | ✅ покрыт         |
| `PUT /volumes/{volume_id}/edit/`      | Редактирование метаданных             | ✅ покрыт         |
| `POST /volumes/{volume_id}/extend/`   | Расширение размера                    | ✅ покрыт         |
| `DELETE /volumes/{volume_id}/`        | Удаление тома                         | ✅ покрыт         |
| `POST /volumes/{volume_id}/attach/`   | Привязка к VM                         | ⏳ не реализовано |
| `DELETE /volumes/{volume_id}/detach/` | Отвязка от VM                         | ⏳ не реализовано |

---

## Инфраструктурные детали

- Для тестов используются реальные RabbitMQ, Postgres и директория (`/dev/vdb`)
- Создаётся временное хранилище (localfs), очищается после каждого теста
- Все тесты независимы и изолированы друг от друга

---

## Запуск тестов

```
cd openvair/modules/volume/tests/
pytest -v
```

- Управлять логами и порядком можно через `pytest.ini`
- Для удобства используйте плагины/интеграцию pytest в IDE (VSCode, PyCharm)

---

## Примечания

- В текущей реализации тесты запускаются вручную после изменений в коде
- При необходимости могут быть легко встроены в CI/CD pipeline
