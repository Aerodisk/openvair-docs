# FAQ по модулю template

---

### ❓ Что такое шаблон (template) и зачем он нужен?

**Шаблон** — это специальный образ (qcow2/raw), который используется как основа
для быстрого создания новых виртуальных дисков (volumes) в едином стандарте.  
Позволяет развертывать инфраструктуру с повторяемыми параметрами, минимизирует
ошибки и ускоряет создание новых VM.

---

### ❓ Как создать шаблон?

- Необходимо выбрать существующий том (volume), который будет "прототипом".
- Через API/интерфейс создать новый шаблон: будет создан новый файл (копия или
  backing-файл) в storage.
- Поддерживаются два типа шаблонов: полная копия (`qemu-img convert`) и шаблон с
  backing-файлом (`qemu-img create -b`).

---

### ❓ Можно ли редактировать или удалять шаблон?

- **Редактировать** имя/описание можно только если шаблон **не используется**
  volumes.
- **Удалить** — запрещено, если на шаблон ссылаются созданные из него тома (
  через backing-файл).
- Любая попытка нарушить правило приводит к ошибке 409 Conflict.

---

### ❓ Какие статусы бывают у шаблона?

- `available` — шаблон готов к использованию.
- `creating` — шаблон в процессе создания/импорта.
- `deleting` — шаблон помечен на удаление, освобождаются ресурсы.
- `error` — ошибка при создании/удалении/операциях.

---

### ❓ Можно ли узнать, какие volumes используют шаблон?

- Да, информация о связанных томах хранится на уровне системы (через RPC).
- Вся связь не через ForeignKey, а через логику модуля volume — каждый volume
  знает, из какого шаблона он создан.

---

### ❓ Можно ли изменить файл шаблона вручную на storage?

- Категорически не рекомендуется.
- Все операции над файлами шаблонов должны проходить только через API модуля
  template — иначе возможны нарушения целостности, потеря данных или сбой всей
  платформы.

---

### ❓ Какие ограничения есть на имена и форматы шаблонов?

- Имя шаблона уникально в пределах хранилища (storage).
- Допустимые форматы: только `qcow2`

---

### ❓ Можно ли создать новый шаблон на основе уже существующего шаблона?

- Да, поддерживается "наследование" — новый шаблон может быть создан на базе
  существующего, включая возможность использовать его как backing-файл.

---

### ❓ Как устроена безопасность операций с шаблонами?

- Любые ошибки или сбои фиксируются, шаблон переходит в статус `error`.
- Все операции логируются для аудита.
- Проверяется валидность и целостность файла на storage при каждой операции.

---

### ❓ Какие проверки выполняются перед удалением шаблона?

- Система проверяет отсутствие связанных volumes через RPC.
- Если связи есть — операция блокируется, возвращается подробное описание
  причины.

---

### ❓ Можно ли использовать шаблоны из разных хранилищ (storage)?

- Да, при создании шаблона указывается, в каком storage хранить файл.
- Система поддерживает работу с несколькими хранилищами (localfs, nfs и т.д.),
  если они подключены и поддерживаются платформой.

---
