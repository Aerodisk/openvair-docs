# Тесты модуля template

## Цели тестирования

- Проверка корректной работы публичных API-эндпоинтов модуля `template`
- Обеспечение соответствия бизнес-логике управления шаблонами томов
- Выявление и предотвращение регрессий после изменений в коде
- Документирование допустимого и ошибочного поведения
- Проверка граничных сценариев: валидация, авторизация, статусы, ошибки БД и RPC
- Безопасное развитие и рефакторинг функционала

---

## Подход к тестированию

Тесты для template построены как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Тесты имитируют реальные RPC-вызовы (`RabbitMQ`) и операции с БД (Postgres)
- Проверяются все сценарии: создание, редактирование, удаление, получение
  шаблонов, права доступа, ошибки, некорректные UUID, валидация по длине/формату
- Есть позитивные (успех) и негативные кейсы (валидация, права, ошибки
  ресурсов/статусов)

---

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек тестирования
- Генерация входных данных через `pydantic`, UUID, SQLAlchemy
- Окружение конфигурируется `.env.test`, фикстуры, очистка данных после каждого
  теста
- Логгирование операций и ошибок через общий логгер проекта

## Структура файлов

```
tests/
│
├── api/
│   ├── test_create.py      # POST /templates/
│   ├── test_delete.py      # DELETE /templates/{id}
│   ├── test_edit.py        # PATCH /templates/{id}
│   ├── test_retrive.py     # GET /templates/ и /templates/{id}
│
├── conftest.py             # Общие фикстуры и подготовка окружения
├── config.py               # Конфигурация тестовой среды
├── .env.test               # Переменные среды для тестов
├── pytest.ini              # Порядок запуска, логирование
```

---

## Используемые фикстуры

- **client**: FastAPI TestClient с настройками тестового приложения
- **unauthorized_client**: TestClient без подмены авторизации — для негативных
  кейсов
- **mock_auth_dependency**: подмена JWT-аутентификации
- **configure_pagination**: поддержка пагинации FastAPI
- **storage**: создание и удаление временного хранилища для шаблонов
- **volume**: создание и удаление тестового тома
- **template**: создание и удаление тестового шаблона
- **cleanup_all_volumes / cleanup_all_templates**: удаление всех томов и
  шаблонов после тестов

## Покрытие эндпоинтов

| Эндпоинт                          | Назначение                               | Статус   |
|-----------------------------------|------------------------------------------|----------|
| `POST /templates/`                | Создание шаблона                         | ✅ покрыт |
| `GET /templates/`                 | Получение списка шаблонов (с пагинацией) | ✅ покрыт |
| `GET /templates/{template_id}`    | Получение шаблона по ID                  | ✅ покрыт |
| `PATCH /templates/{template_id}`  | Изменение имени и описания шаблона       | ✅ покрыт |
| `DELETE /templates/{template_id}` | Удаление шаблона по ID                   | ✅ покрыт |

---

## Инфраструктурные детали

- Все тесты используют реальные RPC-вызовы, Postgres, файловые директории для
  шаблонов и томов
- Используется тестовое хранилище (storage), создаётся и удаляется для каждого
  теста
- Каждый тест изолирован, порядок не влияет на результат

---

## Запуск тестов

```
cd openvair/modules/template/tests/
pytest -v
```

- Управление логами и порядком — через `pytest.ini`
- Для удобства используйте плагины/интеграцию pytest в IDE (VSCode, PyCharm)

---

## Примечания

- Все тесты используют TestClient и реальные RPC
- Перед запуском тестов требуется подготовленное окружение (PostgreSQL,
  RabbitMQ, директории для шаблонов/томов)
- Тесты покрывают позитивные/негативные кейсы: права доступа, ошибки валидации,
  удалённые/несуществующие ресурсы, асинхронность статусов
- Могут быть масштабированы для CI/CD pipeline
