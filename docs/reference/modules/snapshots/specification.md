# Документация функционала снапшотов (модуль виртуальных машин)

## Основное назначение

Функционал снапшотов (`snapshots`) модуля виртуальных машин (`virtual_machines`) реализует 
управление моментальными снимками состояний виртуальных машин: создание снапшота, 
удаление снапшота, откат виртуальной машины к состоянию снапшота. 

Используются снапшоты **internal**-типа, сохраняющие данные в файле диска виртуальной машины (`.qcow2`).

---

## Архитектура и слои

```
API (FastAPI, entrypoints/ api.py, schemas.py, crud.py)
↓
Service Layer (service_layer/ services.py, unit_of_work.py)
↓
Domain Layer (domain/ base.py, libvirt2/driver.py)
↓
Infrastructure (adapters/ orm.py, repository.py, serializer.py)
```

- **API:** REST endpoint’ы FastAPI, валидация входных данных через Pydantic.
- **Service Layer:** бизнес-логика, мониторинг, работа со статусами,
  интеграция с event_store, транзакции БД, контроль дерева снапшотов в БД.
- **Domain Layer:** работа с libvirt, контроль ограничений, взаимодействие
  с XML-файлами метаданных снапшотов, контроль дерева снапшотов в метаданных.
- **Infrastructure:** работа с БД через ORM, репозитории таблицы снапшотов,
  сериализация/десериализация, Alembic-миграция БД.

## Эндпоинты API

| Метод  | URL                                                  | Описание                                          |
|--------|------------------------------------------------------|---------------------------------------------------|
| GET    | /virtual-machines/{vm_id}/snapshots/                 | Получить список снапшотов виртуальной машины      |
| GET    | /virtual-machines/{vm_id}/snapshots/{snap_id}        | Получить информацию о снапшоте ВМ                 |
| POST   | /virtual-machines/{vm_id}/snapshots/                 | Создать новый снапшот виртуальной машины          |
| POST   | /virtual-machines/{vm_id}/snapshots/{snap_id}/revert | Откатить состояние виртуальной машины до снапшота |
| DELETE | /virtual-machines/{vm_id}/snapshots/{snap_id}        | Удалить снапшот виртуальной машины                |


### Подробности по эндпоинтам

#### `GET /virtual-machines/{vm_id}/snapshots/`

- Возвращает: список снапшотов виртуальной машины по её ID - `vm_id`.
- Каждый элемент содержит: `vm_id`, `id`, `vm_name`, `name`,
  `parent`, `description`, `created_at`, `is_current`, `status`.
- Получает данные только из БД.

#### `GET /virtual-machines/{vm_id}/snapshots/{snap_id}`

- Возвращает: подробную информацию о снапшоте по ID ВМ - `vm_id` и ID снапшота - `snap_id`.
- Информация содержит: `vm_id`, `id`, `vm_name`, `name`,
  `parent`, `description`, `created_at`, `is_current`, `status`.
- Получает данные только из БД.

#### `POST /virtual-machines/{vm_id}/snapshots/`

- Создаёт снапшот на основе виртуальной машины по её ID - `vm_id`.
- Требует обязательное поле `name` и опциональное поле `description`.
- Перед созданием проверяет состояние ВМ и статус _current_-снапшота.
- Выполняет асинхронный запрос к доменному слою, так как это длительная операция.

#### `POST /virtual-machines/{vm_id}/snapshots/{snap_id}/revert`

- Позволяет откатить состояние виртуальной машины (`vm_id`) до снапшота (`snap_id`).
- Перед откатом проверяет состояние ВМ и статус _current_-снапшота и откатываемого снапшота.
- Выполняет асинхронный запрос к доменному слою, так как это длительная операция.

#### `DELETE /virtual-machines/{vm_id}/snapshots/{snap_id}`

- Удаляет снапшот (`snap_id`) виртуальной машины (`vm_id`). 
- Перед удалением проверяет состояние ВМ и статус удаляемого снапшота.
- Также доступно удаление снапшотов у выключенных ВМ и снапшотов со статусом `error`.
- Удаление снапшота выключенной ВМ происходит через _QEMU_.
- Восстанавливается дерево снапшотов (меняется `parent` у дочерних снапшотов).

## Валидации и исключения

- Все входные данные валидируются на уровне DTO (Pydantic).
- Имя снапшота уникально для каждой виртуальной машины.
- Нельзя работать со снапшотами виртуальной машины, когда она выключена _(кроме удаления)_.
- Для действий со снапшотами снапшоты должны быть иметь статус `running` _(кроме удаления)_.
- При ошибках создания или удаления снапшота, а также при исчезновении снапшота из **_libvirt_**,
  статус снапшота меняется на `error`.
- Нельзя удалять/изменять/переименовывать XML-файлы с метаданными снапшотов в `/openvair/data/snapshots/`.
- Ошибки возвращаются с указанием причины.
- Используются кастомные исключения сервисного и доменного слоёв.
---

## Статусы снапшота (`SnapshotStatus`)

- `running` — снапшот присутствует в системе и используется.
- `creating` — снапшот в процессе создания/переопределения.
- `deleting` — снапшот в процессе удаления.
- `reverting` — происходит откат виртуальной машины к данному снапшоту.
- `error` — ошибка при создании/удалении или исчезновение снапшота из **_libvirt_**.

## ORM

```python
class Snapshots(Base):
    """ORM class mapped to the `snapshots` table."""

    __tablename__ = 'snapshots'

    id: Mapped[uuid.UUID] = mapped_column(
        UUID(),
        primary_key=True,
        default=uuid.uuid4,
    )
    vm_id: Mapped[uuid.UUID] = mapped_column(
        UUID(),
        ForeignKey('virtual_machines.id'),
        nullable=False,
    )
    name: Mapped[str] = mapped_column(
        String(60),
        nullable=False,
    )
    parent_id: Mapped[uuid.UUID] = mapped_column(
        UUID(),
        ForeignKey('snapshots.id'),
        nullable=True,
    )
    description: Mapped[str] = mapped_column(
        String(255),
        nullable=True,
    )
    status: Mapped[str] = mapped_column(
        String(30),
        nullable=False,
    )
    created_at: Mapped[datetime.datetime] = mapped_column(
        DateTime,
        default=datetime.datetime.now,
    )
    is_current: Mapped[bool] = mapped_column(
        Boolean,
        default=False,
        nullable=False,
        index=True
    )

    virtual_machine: Mapped[VirtualMachines] = relationship(
        'VirtualMachines',
        back_populates='snapshots',
    )
    parent: Mapped['Snapshots'] = relationship(
        'Snapshots',
        foreign_keys=[parent_id],
        remote_side=[id],
    )

```

## Особенности

### Работа с файлами метаданных:

_**ПРИМЕЧАНИЕ:**_
_Выключенные ВМ перестают существовать в системе и удаляются из **libvirt**, вместе с этим 
удаляется и информация о снапшотах. Поэтому при запуске ВМ снапшоты перерегистрируются 
в **libvirt** по файлам метаданных._

- Путь сохранения XML-файлов метаданных снапшотов: `~/openvair/data/snapshots/`.
- Метаданные снапшотов в виде XML-файлов сохраняются сразу после создания 
  снапшота в **_libvirt_**.
- При старте (запуске) виртуальной машины происходит восстановление (redefine) 
  снапшотов в **_libvirt_** из их метаданных.
- Формат названия XML-файла: `{vm_name}_{name}.xml`.
- При удалении снапшота в XML-файлах дочерних снапшотов изменяется имя
  parent-снапшота для восстановления дерева снапшотов.

## Мониторинг

- Каждые 10 секунд происходит проверка через **_libvirt_** и обновление статусов снапшотов.
- Если статус снапшота был `creating` и снапшот появился в системе - статус 
  меняется на `running`.
- Если статус снапшота был `reverting` и снапшот в системе стал _current_ - статус 
  снапшота меняется на `running`.
- Если снапшот из базы данных не найден в **_libvirt_** и его статус не `creating` - статус 
  снапшота меняется на `error`.
- Автоматически отмечается флаг `is_current` у _current_-снапшота
  (если нет _current_-снапшота - флаг снимается у всех снапшотов ВМ).

## События и интеграция

- Логирование всех операций через общий _logger_ системы.
- Все значимые события (создание, удаление, откат) фиксируются в event_store.
- Используется механизм RPC (через RabbitMQ) для связи между слоями и с event_store.

---

## Ошибки и типовые ситуации

- `400 Bad Request` — некорректные параметры, неверный формат.

- `401 Unauthorized` — запрос без авторизации.

- `422 Validation Error` — ошибка валидации запроса (например, нет обязательных полей).

- Снапшот получает статус `error` — ошибка создания или исчезновение снапшота из **_libvirt_**.

---

## Ограничения

- Снапшоты создаются в рамках каждой ВМ.
- Формат дисков ВМ - поддерживается только `qcow2`.
- Недоступны операция со снапшотами для выключенных ВМ (кроме удаления)
- Невозможно создание/откат/удаление снапшотов, которые находятся в 
  процессе создания/отката/удаления (по статусам).
- Снапшот нельзя отредактировать после создания (имя, описание).
- Необходима сохранность XML-файлов метаданных снапшотов из локальной директории.

## Требования к безопасности

- При ошибке создания или пропаже снапшота из системы - он переходит в статус `error`.
- Все ошибки логируются стандартным логгером с указанием причины ошибки.
- Все действия логируются для последующего аудита.
