# FAQ по функционалу снапшотов (snapshots)

---

### ❓ Что такое снапшот (snapshot) и зачем он нужен?

**Снапшот** — это моментальный снимок состояния виртуальной машины в определённый 
момент времени, который сохраняет данные диска и состояние памяти, и позволяет 
позже вернуть систему к сохраненному состоянию. Он даёт возможность быстро откатиться 
к стабильным состояниям ВМ.

**_Снапшот не является резервной копией и не предназначен для долгосрочного хранения._**


---

### ❓ Какие статусы бывают у снапшотов?

- `running` — снапшот присутствует в системе и используется.
- `creating` — снапшот в процессе создания/переопределения.
- `deleting` — снапшот в процессе удаления.
- `reverting` — происходит откат виртуальной машины к данному снапшоту.
- `error` — ошибка при операциях со снапшотами или исчезнование снапшота из **_libvirt_**.

---

### ❓ Как создать снапшот?

- Необходимо знать ID существующей включенной виртуальной машины, в которой будет создан снапшот.
- Через API-запрос (`POST /virtual-machines/{vm_id}/snapshots/`) создать новый снапшот, 
  указав его имя и (опционально) описание.
- Создание нового снапшота доступно при статусе `running` у _current_-снапшота.
- После создания - дождаться перевода снапшота из статуса `creation` в `running`.
- Во время создания снапшота ВМ будет в состоянии `paused`.

---

### ❓ Какие ограничения есть на создаваемые снапшоты?

- Имя снапшота должно быть уникально в рамках одной виртуальной машины.
- Максимальное количество снапшотов для виртуальной машины - **10**.
- На данный момент поддерживаются только **internal**-снапшоты, которые сохраняют состояние на 
  диске самой машины - `.qcow2`.
- Допустимы только виртуальные машины с дисками формата `qcow2` 
  (не поддерживаются _raw_-диски).

---

### ❓ Как откатить снапшот?

- Необходимо знать ID существующей включенной виртуальной машины и ID снапшота для отката.
- Через API-запрос (`POST /virtual-machines/{vm_id}/snapshots/{snap_id}/revert`) создать новый снапшот, 
  указав его имя и (опционально) описание.
- Создание нового снапшота доступно при статусе `running` у _current_-снапшота 
  и снапшота, к которому идёт откат.
- После отката - дождаться перевода снапшота из статуса `reverting` в `running`.
- Во время отката снапшота ВМ будет в состоянии `paused`.

---

### ❓ Можно ли редактировать или удалить снапшот?

- Редактировать снапшот нельзя.
- Удалить снапшот можно средствами API по ID виртуальной машины и ID снапшота.
  (`DELETE /virtual-machines/{vm_id}/snapshots/{snap_id}`).
- Удаление снапшота возможно и при выключенной ВМ.
- Возможно удаление снапшота с ошибкой (статусом `error`).

---

### ❓ Как поддерживается дерево снапшотов при удалении снапшота?

- Восстановление дерева снапшотов происходит идентично восстановлению дерева в _**libvirt**_.
- Система заменяет родителя у потомков удаляемого снапшота на его родителя.
- Пример восстановления дерева снапшотов:
```
Изначальное дерево снапшотов:
snap1 (parent: None) -----> snap2 (parent: snap1) -----> snap3 (parent: snap2)
                                                  ∟----> snap4 (parent: snap2)
После удаления снапшота snap2:
snap1 (parent: None) -----> snap3 (parent: snap1)
                     ∟----> snap4 (parent: snap1)
```

---

### ❓ Зачем нужны XML файлы снапшотов?


- XML файлы копируются в `~openvair/data/snapshots` после создания снапшотов.
- Эти файлы хранят метаданные созданных снапшотов.
- Метаданные необходимы для восстановления снапшотов в **_libvirt_** после перезапуска машин
  (так как после выключения виртуальные машины пропадают из системы вместе со снапшотами).

---

### ❓ Что делать, если снапшот имеет статус `error`?

- Как правило, такой статус получают снапшоты, которые не найдены мониторингом в _**libvirt**_.
- Необходимо проверить наличие снапшота (`sudo virsh snapshot-list {vm_name} {snapshot_name}`)
  при включенной ВМ.
- Если снапшот присутствует в _**libvirt**_, но статус всё ещё `error` - попробовать перезапустить ВМ.
- При сохранении ошибки - перезапустить сервис модуля ВМ (`sudo systemctl restart vm-service-layer.service`)
  и повторить действия.

---

### ❓ Как устроена безопасность операций со снапшотами?


- Ошибки фиксируются, при ошибках снапшот переходит в статус `error`.
- Все операции и ошибки логируются для аудита (в стандартных логах и _Event Store_).
