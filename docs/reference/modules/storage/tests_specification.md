# Тесты модуля Storage (LocalFS)

## Цели тестирования

- Проверка работы API-эндпоинтов модуля хранилищ (**`storage`**) **для LocalFS**
- Обеспечение корректности операций создания, удаления и управления хранилищами
- Тестирование работы с **локальными** дисками и разделами (партициями)
- Валидация входных данных и обработка ошибок
- Поддержка стабильности функционала через автоматизированные интеграционные тесты

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Проверяются все основные операции жизненного цикла хранилищ и разделов дисков
- Тесты взаимодействуют с реальной файловой системой
- Все сценарии изолированы через фикстуры очистки данных

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования
- Реальная файловая система для работы с дисками и разделами
- База данных PostgreSQL для хранения метаданных хранилищ
- Автоматическая очистка тестовых данных после каждого теста

## Структура файлов
```
tests/
├── conftest.py # Фикстуры модуля
└── api/
    └── localfs/
        ├── test_create.py # POST /storages/create/, /storages/local-disks/create_partition/
        ├── test_delete.py # DELETE /storages/{id}/delete/, /storages/local-disks/delete_partition/
        └── test_retrive.py # GET /storages/, /storages/{id}/, /storages/local-disks/
```


## Используемые фикстуры

- `cleanup_storages` - очищает все хранилища до и после каждого теста
- `target_disk_path` - предоставляет путь к тестовому диску с очисткой созданных разделов
- `local_partition` - создает тестовый раздел на диске
- `storage` - создает тестовое хранилище LocalFS
- `client` - стандартный тестовый клиент FastAPI с аутентификацией
- `unauthorized_client` - клиент без авторизации для проверки доступа

## Покрытие эндпоинтов

| Эндпоинт                                  | Метод   | Назначение                        | Статус покрытия    |
|-------------------------------------------|---------|-----------------------------------|--------------------|
| `/storages/`                              | GET     | Получение списка хранилищ         | ✅ покрыт           |
| `/storages/{storage_id}/`                 | GET     | Получение хранилища по ID         | ✅ покрыт           |
| `/storages/create/`                       | POST    | Создание хранилища                | ✅ покрыт (LocalFS) |
| `/storages/{storage_id}/delete/`          | DELETE  | Удаление хранилища                | ✅ покрыт (LocalFS) |
| `/storages/local-disks/`                  | GET     | Получение списка локальных дисков | ✅ покрыт           |
| `/storages/local-disks/create_partition/` | POST    | Создание раздела на диске         | ✅ покрыт           |
| `/storages/local-disks/delete_partition/` | DELETE  | Удаление раздела диска            | ✅ покрыт           |
| `/storages/local-disks/partition_info/`   | GET     | Получение информации о разделах   | ✅ покрыт           |

## Основные тестовые сценарии

### 1. Успешные операции (Проверка HTTP 200/201, валидация полей ответа)
- Создание LocalFS-хранилища с валидными параметрами
- Создание раздела на локальном диске
- Удаление хранилища и разделов
- Получение списка хранилищ и информации о дисках/партициях

### 2. Обработка ошибок валидации
- Отсутствие обязательных полей
- Невалидные форматы данных
- Неподдерживаемые типы файловых систем
- Попытка создания с дублирующимся путём

### 3. Ошибки инфраструктуры
- Создание хранилища с несуществующим путем
- Создание раздела на несуществующем диске
- Недостаточное место для создания раздела
- Удаление несуществующих ресурсов

### 4. Проверка доступа
- Все защищенные эндпоинты возвращают HTTP 401 для неавторизованных запросов
- Корректная работа с авторизованным доступом

### 5. Пограничные случаи
- Работа с пустыми списками хранилищ
- Получение информации о разделах пустого диска

## Инфраструктурные детали

- Для тестов используется выделенный тестовый диск, указанный в `.env.test`:
```
TEST_STORAGE_PATH=/dev/vdb
```
- Диск должен иметь разметку **GPT** (GUID Partition Table)
- Рекомендуется использовать **не-NVMe** диск для корректной работы с разделами
- Все созданные тестовые объекты автоматически очищаются после каждого теста
- Тесты используют реальную файловую систему и проверяют наличие разделов дисков

## Запуск тестов

```shell
cd openvair/modules/storage/tests/api/localfs
pytest -v
```

## Примечания
- На данный момент тесты работают **только с LocalFS хранилищами** (тесты NFS будут реализованы в будущем)
- Для корректной работы тестов тестовый диск должен удовлетворять указанным требованиям 
- Все тесты полностью изолированы друг от друга
- Автоматическая очистка обеспечивает стабильность тестовых прогонов
