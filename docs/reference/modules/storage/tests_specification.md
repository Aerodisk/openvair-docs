# Тесты модуля Storage

## Цели тестирования

- Проверка работы API-эндпоинтов модуля хранилищ (**`storage`**) для **LocalFS и NFS**
- Обеспечение корректности операций создания, удаления и управления хранилищами (LocalFS/NFS)
- Тестирование работы с локальными дисками и разделами (партициями)
- Валидация входных данных и обработка ошибок
- Поддержка стабильности функционала через автоматизированные интеграционные тесты

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Проверяются все основные операции жизненного цикла хранилищ и зависимых ресурсов
- LocalFS: работа с реальным тестовым диском и файловой системой
- NFS: работа с реальным NFS-сервером
- Все сценарии изолированы фикстурами, обеспечивающими очистку ресурсов

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования
- LocalFS: реальная файловая система и работа с разделами дисков
- NFS: взаимодействие с удалённым сервером NFS
- PostgreSQL — база данных для хранения метаданных
- Автоматическая очистка тестовых данных после каждого теста

## Используемые фикстуры

- `cleanup_storages` — очищает все хранилища до и после каждого теста
- `client` — авторизованный тестовый клиент FastAPI
- `unauthorized_client` — клиент без авторизации для проверки доступа

- `target_disk_path` — путь к тестовому диску с очисткой разделов
- `local_partition` — создаёт тестовый раздел
- `storage` — создаёт тестовое хранилище (`localfs` или `nfs` в зависимости от параметризации, по умолчанию - `localfs`)
- `volume` — создаёт и удаляет том в хранилище
- `template` — создаёт и удаляет шаблон на основе тома

## Основные тестовые сценарии

### 1. Успешные операции (Проверка HTTP 200/201, валидация полей ответа)
- Создание хранилища (LocalFS/NFS) с валидными параметрами
- Удаление хранилища
- Создание и удаление разделов на локальном диске (LocalFS)
- Получение списка хранилищ и информации о дисках/партициях

### 2. Обработка ошибок валидации
- Отсутствие обязательных полей
- Невалидные форматы данных
- Некорректный путь/диск (LocalFS)
- Некорректный IP или путь (NFS)
- Дублирующее имя хранилища

### 3. Ошибки инфраструктуры
- Создание хранилища с несуществующим путем / некорректным IP
- Создание раздела на несуществующем диске
- Недостаточное место для создания раздела
- Удаление несуществующих ресурсов
- Удаление хранилища с томами/шаблонами

### 4. Проверка доступа
- Все защищенные эндпоинты возвращают HTTP 401 для неавторизованных запросов

### 5. Пограничные случаи
- Работа с пустыми списками хранилищ
- Получение информации о разделах пустого диска

## Инфраструктурные детали

### LocalFS
- Для тестов используется выделенный тестовый диск, указанный в `.env.test`:
```
TEST_STORAGE_PATH=/dev/vdb
```
- Диск должен иметь разметку **GPT** (GUID Partition Table)
- Рекомендуется использовать **не-NVMe** диск для корректной работы с разделами
- Все созданные тестовые объекты автоматически очищаются после каждого теста
- Тесты используют реальную файловую систему и проверяют наличие разделов дисков

### NFS
- Для тестов требуется доступ к настроенному NFS-серверу, краткая инструкция по настройке:
```shell
# Допустим, что 192.168.5.155 - IP-адрес сервера

# Настройка сервера:
sudo apt-get install nfs-kernel-server
sudo mkdir /var/tmp/nfs_share
sudo chmod 777 /var/tmp/nfs_share
sudo chown nobody:nogroup /var/tmp/nfs_share
sudo nano /etc/exports  # Здесь в конце файла нужно прописать строку: /var/tmp/nfs_share *(rw,sync,no_root_squash)
sudo exportfs -arvf
systemctl start nfs-kernel-server

# Настройка клиента:
sudo apt-get install nfs-common
sudo mkdir ~/nfs_client_side
showmount -e 192.168.5.155  # Должно отобразиться "/var/tmp/nfs_share *"
sudo mount -t nfs 192.168.5.155:/var/tmp/nfs_share ~/nfs_client_side
```
- Параметры указываются в `.env.test`:
```
TEST_STORAGE_NFS_IP=192.168.0.1  # IP-адрес заранее настроенного NFS-сервера
TEST_STORAGE_NFS_PATH=/var/tmp/nfs_share  # Путь к настроенному каталогу NFS-сервера
```
- Все тестовые объекты автоматически очищаются фикстурами


## Запуск тестов

```shell
# LocalFS
cd openvair/modules/storage/tests/api/localfs
pytest -v

# NFS
cd openvair/modules/storage/tests/api/nfs
pytest -v
```

## Примечания
- На данный момент для NFS-тестов требуется настроенный и работающий NFS сервер 
  (например, на другой ВМ, связанной с тестовой сетевым мостом).
- Для корректной работы тестов тестовый диск должен удовлетворять указанным требованиям 
- Все тесты полностью изолированы друг от друга
- Автоматическая очистка обеспечивает стабильность тестовых прогонов
