# Тесты модуля Virtual Machines

## Цели тестирования

- Проверка работы всех API-эндпоинтов модуля виртуальных машин (`virtual_machines`)
- Обеспечение корректности операций полного жизненного цикла ВМ: 
   создание, удаление, управление состоянием, клонирование, редактирование
- Тестирование функционала снапшотов ВМ: создание, удаление, откат, получение
- Проверка интеграции с **libvirt** и работы VNC-доступа
- Документирование поведения системы при различных сценариях работы с виртуальными машинами
- Поддержка стабильности функционала через автоматизированные интеграционные тесты

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Проверяются все основные операции жизненного цикла виртуальных машин
- Тесты взаимодействуют с реальной реализацией **libvirt** и системой виртуализации
- Все сценарии изолированы через фикстуры очистки ВМ и связанных ресурсов
- Проверяются как позитивные, так и негативные сценарии (валидация, ошибки, edge cases)

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования
- Реальная реализация **libvirt** для работы с виртуальными машинами
- Интеграция с реальной БД PostgreSQL и брокером сообщений RabbitMQ
- Конфигурация через `.env.test`: переменные `TEST_STORAGE_PATH` и `TEST_STORAGE_FS_TYPE` для создания storage
- Автоматическая очистка тестовых ВМ, снапшотов и прочих связанных ресурсов после каждого теста

## Структура файлов
```
openvair/
    └── modules/
        └── virtual_machines/
            └── tests/
                ├── conftest.py # Фикстуры модуля (cleanup_vms, vm_snapshot)
                └── api/
                    └── virtual_machines/
                        ├── test_create.py # POST /virtual-machines/create/, /virtual-machines/{id}/clone/
                        ├── test_delete.py # DELETE /virtual-machines/{id}/
                        ├── test_edit.py # POST /virtual-machines/{id}/edit/
                        ├── test_manage.py # POST /virtual-machines/{id}/start/, /shut-off/, GET /vnc/
                        ├── test_retrieve.py # GET /virtual-machines/, /virtual-machines/{id}/
                    └── snapshots/
                        ├── test_snap_create.py # POST /virtual-machines/{vm_id}/snapshots/
                        ├── test_snap_delete.py # DELETE /virtual-machines/{vm_id}/snapshots/{snap_id}
                        ├── test_snap_manage.py # POST /virtual-machines/{vm_id}/snapshots/{snap_id}/revert
                        └── test_snap_retrieve.py # GET /virtual-machines/{vm_id}/snapshots/, /{snap_id}
    └── conftest.py # Общие фикстуры (virtual_machine и др.)
```

## Используемые фикстуры

- **cleanup_vms**: Удаляет все тестовые ВМ и связанные ресурсы до и после теста
- **vm_create_data**: Возвращает базовые данные для создания ВМ
- **vm_edit_data**: Возвращает данные для редактирования ВМ
- **virtual_machine**: Создает тестовую ВМ и удаляет после теста
- **deactivated_virtual_machine**: Создает выключенную ВМ
- **activated_virtual_machine**: Создает запущенную ВМ
- **vm_snapshot**: Создает снапшот ВМ и удаляет после теста
- **client**: Стандартный тестовый клиент FastAPI с аутентификацией
- **unauthorized_client**: Клиент без авторизации для проверки доступа

## Ключевые тест-кейсы

### 1. Создание и клонирование ВМ
- **Успешное создание ВМ** — проверка HTTP 201, создание в libvirt
- **Создание с автоматическим созданием тома** — проверка интеграции с модулем volume
- **Валидация данных** — невалидные CPU, RAM, OS, MAC, интерфейсы, диски
- **Ошибки инфраструктуры** — несуществующий том, дублирующееся имя
- **Клонирование ВМ** — успешное, множественное, с валидацией параметров

### 2. Удаление ВМ
- **Успешное удаление** — проверка удаления из БД и libvirt
- **Ошибки состояний** — удаление запущенной ВМ, ВМ в невалидных статусах
- **Удаление со снапшотами** — проверка каскадного удаления

### 3. Редактирование ВМ
- **Изменение метаданных** — имени, описания
- **Изменение конфигурации** — добавление/удаление дисков, сетевых интерфейсов
- **Валидация** — редактирование запущенной ВМ, дублирующееся имя

### 4. Управление состоянием ВМ
- **Запуск/остановка** — успешные сценарии, проверка состояний в libvirt
- **Ошибки переходов** — запуск уже запущенной, остановка уже остановленной
- **VNC доступ** — успешный доступ, ошибки для остановленной/несуществующей ВМ

### 5. Снапшоты ВМ
- **Создание снапшотов** — успешное, цепочки снапшотов, валидация имен
- **Управление снапшотами** — откат, проверка восстановления цепочек
- **Удаление снапшотов** — успешное, из цепочек, каскадное удаление
- **Интеграция с libvirt** — проверка реального состояния снапшотов

### 6. Ошибки авторизации
- Все защищённые эндпоинты проверены на HTTP 401 для неавторизованных запросов

### 7. Пограничные случаи
- Невалидные UUID форматы
- Работа с несуществующими ресурсами
- Валидация входных данных (длины строк, диапазоны значений)
- Обработка асинхронных операций через утилиты ожидания

## Инфраструктурные детали

- Для работы тестов требуется настроенное окружение виртуализации с **libvirt**
- В `.env.test` необходимо указать:
```env
    TEST_STORAGE_PATH=/path/to/test/storage
    TEST_STORAGE_FS_TYPE=ext4
```
- Используются существующие фикстуры проекта (storage, volume), что обеспечивает согласованность тестовой среды
- Очистка тестовых данных включает удаление ВМ из БД и libvirt, а также связанных ресурсов (томов, хранилищ)
- Реализовано ожидание изменения статусов через wait_for_field_value() для асинхронных операций
- Для снапшотов используется увеличенный таймаут (SNAPSHOT_TIMEOUT = 120)

```

```

## Примечания
- Тесты являются интеграционными и требуют доступа к реальному libvirt
- Должны удовлетворяться требования и зависимости для создания вспомогательных ресурсов (volume, storage)
- Используются комплексные тесты с многочисленными длительными (асинхронными) операциями - 
  выполнение тестов может занимать продолжительное время
- Для корректной работы необходимо предварительно указать путь к созданию хранилища в `.env.tests`
- Тесты покрывают сложные сценарии: цепочки снапшотов, клонирование нескольких ВМ и др.
- Основные операции проверяются как на уровне API, так и на уровне реального состояния в libvirt
- Тесты независимы и могут выполняться в любом порядке благодаря комплексной очистке
- Могут быть интегрированы в CI/CD pipeline
