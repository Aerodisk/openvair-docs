# Тесты модуля Event Store

## Цели тестирования

- Проверка работы API-эндпоинтов модуля системных событий (**`event_store`**)
- Обеспечение корректности операций получения и экспорта событий системы
- Тестирование пагинации, фильтрации по модулям и формата данных
- Документирование поведения системы при различных сценариях работы с событиями
- Поддержка стабильности функционала через автоматизированные интеграционные тесты

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Проверяются все основные операции работы с событиями
- Тесты взаимодействуют с реальной базой данных через RPC-клиент
- Все сценарии изолированы через фикстуры очистки событий

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования
- RPC-клиент для создания тестовых событий
- База данных PostgreSQL для хранения событий
- Автоматическая очистка тестовых событий после каждого теста

## Структура файлов
```
└── tests/  
	├── conftest.py  # Фикстуры для тестов  
	└── api/  
	    └── test_retrive.py  # GET /event/, /event/download
```


## Используемые фикстуры

- `cleanup_events` - очищает все события до и после каждого теста
- `created_event` - создает тестовое событие через RPC-клиент и возвращает его данные
- `multiple_events` - создает несколько тестовых событий для тестирования пагинации и фильтрации
- `client` - стандартный тестовый клиент FastAPI с аутентификацией
- `unauthorized_client` - клиент без авторизации для проверки доступа

## Покрытие эндпоинтов

| Эндпоинт          | Метод | Назначение                              | Статус покрытия |
|-------------------|-------|-----------------------------------------|-----------------|
| `/event/`         | GET   | Получение списка событий с пагинацией   | ✅ покрыт       |
| `/event/download` | GET   | Скачивание событий в формате CSV        | ✅ покрыт       |

## Ключевые тест-кейсы

1. **Успешные операции** (проверка HTTP-кодов, валидации ответов):
     - Получение списка событий:
         * `GET /event/` — возвращает `HTTP 200 OK`, корректную структуру пагинации
         * Проверка наличия созданного события в результатах
     - Скачивание событий в CSV:
         * `GET /event/download` — возвращает `HTTP 200 OK`
         * Валидация структуры CSV (заголовки, данные)

2. **Фильтрация и пагинация**:
     - Фильтрация событий по модулю:
         * `GET /event/?module_name=module_name` — возвращает только события указанного модуля
     - Пагинация результатов:
         * `GET /event/?page=1&size=2` — корректно ограничивает количество результатов
     - Обработка невалидных параметров пагинации:
         * `GET /event/?page=-1&size=0` — возвращает `HTTP 422 Unprocessable Entity`

3. **Обработка edge cases**:
     - Получение событий из пустой базы:
         * `GET /event/` — возвращает пустой список с `total: 0`
     - Скачивание CSV при отсутствии событий:
         * `GET /event/download` — возвращает CSV только с заголовками
     - Фильтрация по несуществующему модулю:
         * `GET /event/?module_name=storages` — возвращает пустой результат 
            (так как все события других модулей удалены фикстурой перед тестом)

4. **Ошибки авторизации**:
     - Оба эндпоинта:
         * Проверка `HTTP 401 Unauthorized` для неавторизованных запросов

## Инфраструктурные детали

- Тесты используют RPC-клиент (`EventStoreServiceLayerRPCClient`) для создания тестовых событий
- Все события автоматически очищаются перед и после каждого теста
- Поддерживается фильтрация по любому модулю проекта
- CSV-файл содержит все поля события
- Тесты независимы и могут выполняться в любом порядке

## Запуск тестов

```shell
cd openvair/modules/event_store/tests/
pytest -v
```

Примечания
- Тесты работают с реальной БД и RPC-клиентом
- Для создания тестовых событий используется прямой вызов RPC-методов, что обеспечивает 
  приближенность к реальным условиям
- Формат данных CSV соответствует данным в базе данных
- Все тесты полностью изолированы друг от друга благодаря автоматической очистке событий в БД
