# Тесты модуля network

## Цели тестирования

- Проверка работы API-эндпоинтов модуля сетевых интерфейсов (**`network`**).
- Обеспечение корректности операций с сетевыми интерфейсами и мостами.
- Тестирование интеграции и поддержка **как OVS, так и Netplan**.
- Документирование поведения системы при различных сценариях работы с сетью.
- Поддержка стабильности функционала через автоматизированные интеграционные тесты.

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`.
- Проверяются основные операции жизненного цикла мостов и интерфейсов.
- Тесты взаимодействуют с реальной реализацией **_Open vSwitch (OVS)_** и **_Netplan_**.
- Сценарии изолированы через фикстуры очистки тестовых мостов и подготовки состояний интерфейсов.

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования.
- Взаимодействие с реальными сетевыми менеджерами (**OVS/Netplan**)
- Конфигурация тестовых переменных через `.env.test`: переменная `TEST_NETWORK_INTERFACE` - сеть (интерфейс) для тестов.
- Автоматическая очистка тестовых мостов после каждого теста.
- Проверка работы сети после создания и удаления мостов.

```
                └── test_manage.py       # PUT /interfaces/{name}/turn_on, /interfaces/{name}/turn_off
```


## Используемые фикстуры

- `physical_interface` - получает интерфейс из системы по имени из конфигурации
- `bridge` - создает тестовый мост и удаляет его после теста
- `cleanup_bridges` - очищает все тестовые мосты до и после теста
- `check_manager` - отвечает за пропуск тестов, которые относятся не к текущему сетевому менеджеру (OVS/Netplan)
- `interface_without_ip` - физический интерфейс без IP-адреса
- `pre_turned_off_interface` - переводит интерфейс в состояние 'DOWN' перед тестом (и включает после теста)
- `pre_turned_on_interface` - переводит интерфейс в состояние 'UP' перед тестом (и после теста)
- `pytest_configure` - задаёт кастомные маркеры для OVS/Netplan

## Покрытие эндпоинтов (основные)

| Эндпоинт                      | Метод | Назначение                                     | Статус покрытия |
|-------------------------------|-------|------------------------------------------------|-----------------|
| `/interfaces/`                | GET   | Получение списка интерфейсов                   | ✅ покрыт        |
| `/interfaces/{id}/`           | GET   | Получение интерфейса по id                     | ✅ покрыт        |
| `/interfaces/bridges/`        | GET   | Получение списка мостов                        | ✅ покрыт        |
| `/interfaces/create/`         | POST  | Создание моста                                 | ✅ покрыт        |
| `/interfaces/delete/`         | DELETE| Удаление мостов                                | ✅ покрыт        |
| `/interfaces/{name}/turn_on`  | PUT   | Включение интерфейса (UP, для моста - UNKNOWN) | ✅ покрыт        |
| `/interfaces/{name}/turn_off` | PUT   | Выключение интерфейса (DOWN)                   | ✅ покрыт        |

## Ключевые тест-кейсы

1. **Успешные операции** (проверка HTTP-кодов, валидации ответов)
     - Создание моста:
         * `POST /interfaces/create/` — возвращает `HTTP 201 CREATED`, 
           обязательные поля присутствуют, мост создаётся в OVS/Netplan, работа сети не нарушена.
     - Получение интерфейса / списка интерфейсов / списка мостов:
         * `GET /interfaces/{id}/` `GET /interfaces/`, `GET /interfaces/bridges/` 
           — `HTTP 200 OK`, структура ответа валидна.
     - Удаление моста:
         * `DELETE /interfaces/delete/` — `HTTP 202 ACCEPTED`, статус `deleting` → конечное удаление из БД, 
            из OVS/NETPLAN, работа сети не нарушена.
     - Включение/выключение интерфейса:
         * `PUT /interfaces/{name}/turn_on` / `turn_off` — `HTTP 200 OK`, `power_state` меняется на необходимый.

2. **Ошибки авторизации**
     - Для всех эндпоинтов проверяется `HTTP 401` при запросах от `unauthorized_client`.

3. **Ошибки инфраструктуры**
     - Попытка создать мост на несуществующем интерфейсе —
       либо `HTTP 500`, либо `HTTP 201` + статус `error`.
     - Удаление несуществующего моста — `HTTP 500` с сообщением об ошибке.
     - Пустой список для удаления — корректный `HTTP 202` и пустой ответ.

4. **Пограничные случаи**
     - Попытка выключить/включить несуществующий интерфейс — `HTTP 500` с текстом ошибки.
     - Неверный формат входных данных — проверка на `HTTP 422/500` в зависимости от реализации.

## Инфраструктурные детали

- В `.env.test` необходимо обязательно указывать сетевой интерфейс для тестов — `TEST_NETWORK_INTERFACE` 
  (по умолчанию `eth0`), он должен быть физическим (тип `physical`), единственным `default` и иметь доступ к сети.
- В системе быть как минимум один `physical` интерфейс без заданного IP-адреса (состояние интерфейса не важно).  
- В качестве сетевого менеджера поддерживается как **OVS**, так и **Netplan** - тесты учитывают специфику поведения 
  менеджеров, тесты неактуального сетевого менеджера **_пропускаются_**. 
- Очистка тестовых мостов реализована в `openvair.libs.testing.utils.cleanup_test_bridges()`.
- Реализовано ожидание изменения статусов и состояний через `wait_for_field_value()` для асинхронных операций.
- Все тесты независимы.

## Запуск тестов
```shell
cd openvair/modules/network/tests/
pytest -v
```

## Примечания

- Тесты — интеграционные и предполагают доступ к реальному сетевому интерфейсу, работая с OVS и Netplan.
- Переключение между OVS и Netplan осуществляется **вручную**, путём смены переменной в `project_config.toml`.
- Для Netplan должна быть заранее подготовлена конфигурация в `/etc/netplan/` (например, `01-base-config.yaml`).
- Переменная `TEST_NETWORK_INTERFACE` в `.env.test` должна указывать на `physical` интерфейс (`default`, 
  с сетевым подключением).
- Утилита `cleanup_test_bridges()` удаляет только мосты, созданные для тестов.
- Некоторые тесты (отдельно для Neptlan и OVS) отключены до фикса багов с соответствующими примечаниями (`TODO`).
