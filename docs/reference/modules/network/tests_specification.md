# Тесты модуля network

## Цели тестирования

- Проверка работы API-эндпоинтов модуля сетевых интерфейсов (`network`).
- Обеспечение корректности операций с мостами (bridge) и состоянием интерфейсов.
- Тестирование получения/создания/удаления интерфейсов/мостов и взаимодействия с OVS.
- Документирование поведения системы при различных сценариях
- Поддержка стабильности функционала через автоматизированные интеграционные тесты.

## Подход к тестированию

Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`.
- Проверяются основные операции жизненного цикла мостов и интерфейсов.
- Тесты взаимодействуют с реальным **_Open vSwitch (OVS)_** и БД.
- Сценарии изолированы через фикстуры очистки (удаление тестовых мостов) и подготовки состояний интерфейсов.

## Организация и инструменты

- `pytest`, `fastapi.testclient` — основной стек для тестирования.
- Взаимодействие с OVS через `OVSManager` и `OVSInterface`.
- Конфигурация тестовых переменных через `.env.test` (переменная `TEST_NETWORK_INTERFACE` - сеть для тестов).
- Утилиты очистки/вспомогательные функции - в `openvair.libs.testing.utils`.

## Структура файлов

```
openvair/
└── modules/
    └── network/
        └── tests/
            ├── conftest.py              # Фикстуры модуля (cleanup_bridges, non_default_interface, pre_turned_on/off)
            └── api/
                ├── test_create.py       # POST /interfaces/create/
                ├── test_delete.py       # DELETE /interfaces/delete/
                ├── test_retrive.py      # GET /interfaces/, /interfaces/bridges/, /interfaces/{id}/
                └── test_manage.py       # PUT /interfaces/{name}/turn_on, /interfaces/{name}/turn_off
```


## Используемые фикстуры

- **cleanup_bridges**: удаляет тестовые мосты (до и после теста).
- **physical_interface**: физический интерфейс по умолчанию (берётся из конфига `.env.test`).
- **non_default_interface**: другой физический интерфейс, без IP.
- **pre_turned_off_interface / pre_turned_on_interface**: переводят интерфейс в нужное состояние до и после теста.
- **bridge**: фикстура, создающая мост (используется тестами удаления и модификации).

## Покрытие эндпоинтов (основные)

| Эндпоинт                       | Метод | Назначение                                 | Статус покрытия              |
|--------------------------------|-------|--------------------------------------------|------------------------------|
| `/interfaces/`                 | GET   | Получение списка интерфейсов (paginated)   | ✅ покрыт                     |
| `/interfaces/{id}/`            | GET   | Получение интерфейса по id                 | ✅ покрыт                     |
| `/interfaces/bridges/`         | GET   | Получение списка мостов                    | ✅ покрыт                     |
| `/interfaces/create/`          | POST  | Создание моста                             | ✅ покрыт                     |
| `/interfaces/delete/`          | DELETE| Удаление мостов                            | ✅ покрыт                     |
| `/interfaces/{name}/turn_on`   | PUT   | Включение интерфейса (power_state → UP)    | 🟨 покрыт (кроме вкл. моста) |
| `/interfaces/{name}/turn_off`  | PUT   | Выключение интерфейса (power_state → DOWN) | 🟨 покрыт (кроме выкл. моста)|

## Ключевые тест-кейсы

1. **Успешные операции** (проверка HTTP-кодов, валидации ответов)
     - Создание моста:
         * `POST /interfaces/create/` — возвращает `HTTP 201 CREATED`, 
           обязательные поля присутствуют, мост создаётся в OVS.
     - Получение интерфейса / списка интерфейсов / списка мостов:
         * `GET /interfaces/{id}/` `GET /interfaces/`, `GET /interfaces/bridges/` 
           — `HTTP 200 OK`, структура ответа валидна.
     - Удаление моста:
         * `DELETE /interfaces/delete/` — `HTTP 202 ACCEPTED`, статус `deleting` → конечное удаление из OVS.
     - Включение/выключение интерфейса:
         * `PUT /interfaces/{name}/turn_on` / `turn_off` — `HTTP 200 OK`, `power_state` меняется 
         (с проверкой через `wait_for_field_value`).

2. **Ошибки авторизации**
     - Для всех эндпоинтов проверяется `HTTP 401` при запросах от `unauthorized_client`.

3. **Ошибки инфраструктуры**
     - Попытка создать мост на несуществующем интерфейсе — ожидается 
       либо `HTTP 500`, либо `HTTP 201` + статус `error`.
     - Удаление несуществующего моста — `HTTP 500` с сообщением об ошибке.
     - Пустой список для удаления — корректный `HTTP 202` и пустой ответ.

4. **Пограничные случаи**
     - Создание моста с пустым списком интерфейсов (может быть успешно создан).
     - Попытка выключить/включить несуществующий интерфейс — `HTTP 500` с текстом ошибки.
     - Неверный формат входных данных — проверка на `HTTP 422/500` в зависимости от реализации.

## Инфраструктурные детали

- Для тестов используется реальная подсистема OVS.
- В `.env.test` необходимо обязательно указывать сетевой интерфейс для тестов —
  `TEST_NETWORK_INTERFACE` (по умолчанию `eth0`) в конфиге тестовой среды. 
  Для корректной проверки создания мостов сеть должна быть единственной `default` на момент тестов.
- Очистка тестовых мостов реализована в `openvair.libs.testing.utils.cleanup_test_bridges()` — 
  удаляются только мосты с префиксом `test-`, чтобы не трогать системные мосты других интерфейсов.

## Запуск тестов
```shell
cd openvair/modules/network/tests/
pytest -v
```

## Примечания

- Тесты — интеграционные и предполагают доступ к реальному сетевому интерфейсу и работу с OVS.
- Переменная `TEST_NETWORK_INTERFACE` в `.env.test` должна указывать на реальный интерфейс (единственный default).
- Утилита `cleanup_test_bridges()` специально удаляет только мосты, созданные для тестов.
- Тесты `test_turn_on_bridge_success()` и `test_turn_off_bridge_success()` закомментированы до фикса соответствующего
  [бага](https://github.com/Aerodisk/openvair/issues/117). 
  Переключение моста нарушает работу сети, такой мост невозможно удалить - это нарушает работу остальных тестов.
