# Тесты модуля backup

## Цели тестирования
- Проверка работы API-эндпоинтов модуля резервного копирования (`backup`)
- Обеспечение корректности операций с бэкапами (резервными копиями)
- Тестирование обработки ошибок при работе с **Restic**
- Документирование поведения системы при различных сценариях работы
- Поддержка стабильности функционала через автоматизированные проверки

## Подход к тестированию
Тесты реализованы как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`
- Проверяются все основные операции жизненного цикла бэкапов
- Тесты взаимодействуют с реальной реализацией **Restic**
- Все сценарии изолированы через фикстуры очистки репозитория

## Организация и инструменты
- `pytest`, `fastapi.testclient` — основной стек для тестирования
- Реальная реализация **Restic** для работы с бэкапами
- Конфигурация через `project_config.toml` с указанием параметров репозитория
- Автоматическая очистка тестового репозитория после каждого теста

## Структура файлов

```
openvair/
└── modules/
    └── backup/
        └── tests/
            ├── conftest.py              # Фикстуры модуля
            └── api/
                ├── test_create.py       # POST /backup/
                ├── test_delete.py       # DELETE /backup/{snapshot_id}
                ├── test_get.py          # GET /backup/
                ├── test_init.py         # POST /backup/repository
                └── test_restore.py      # POST /backup/restore
```

## Используемые фикстуры
- **clean_backup_repository**: Создает и очищает тестовый репозиторий (директорию)
- **backup_repository**: Инициализирует репозиторий бэкапов для тестов
- **backup_snapshot**: Создает тестовый снимок бэкапа
- **client**: Стандартный тестовый клиент FastAPI с аутентификацией
- **unauthorized_client**: Клиент без авторизации для проверки доступа

## Покрытие эндпоинтов
| Эндпоинт                  | Метод | Назначение                | Статус покрытия |
|---------------------------|-------|---------------------------|-----------------|
| `/backup/`                | GET   | Получение списка бэкапов  | ✅ покрыт       |
| `/backup/`                | POST  | Создание нового бэкапа    | ✅ покрыт       |
| `/backup/{snapshot_id}`   | DELETE| Удаление бэкапа           | ✅ покрыт       |
| `/backup/repository`      | POST  | Инициализация репозитория | ✅ покрыт       |
| `/backup/restore`         | POST  | Восстановление из бэкапа  | ✅ покрыт       |

## Ключевые тест-кейсы
1. **Успешные операции** (Проверка HTTP 200, валидация ответа):
     - Инициализация репозитория
     - Создание бэкапа
     - Получение списка бэкапов
     - Восстановление данных
     - Удаление бэкапа

2. **Ошибки авторизации**:
     - Все защищённые эндпоинты
     - Проверка:
         * HTTP 401 для неавторизованных запросов
         * Отсутствие изменений в системе

3. **Ошибки инфраструктуры**:
     - Работа с неинициализированным репозиторием:
         * Соответствующие сообщения об ошибках
         * HTTP 500 статус
     - Повторная инициализация:
         * Проверка обработки конфликта
     - Пустой репозиторий:
         * Корректный возврат пустого списка

4. **Пограничные случаи** (примеры):
     - Восстановление без указания ID:
         * Автоматический выбор последнего бэкапа
     - Удаление несуществующего бэкапа:
         * Сообщение о пропуске удаления (_HTTP 200 и статус `success` в текущей реализации
           из-за особенностей работы Restic_)
     - Структура данных:
         * Проверка обязательных полей бэкапа
         * Валидация форматов данных

## Инфраструктурные детали
- Используется оригинальная конфигурация из `project_config.toml`:

```toml
[backup]
    backuper = 'restic'
    [backup.restic]
    repository = '/srv/restic_repo'
    password = 'your_password'
```

- Тестовый репозиторий полностью изолируется между тестами
- Все тесты независимы и могут выполняться в любом порядке
- Автоматическая очистка данных после каждого теста

## Запуск тестов

```shell
cd openvair/modules/backup/tests/
pytest -v
```

## Примечания
- Для работы тестов должен быть [корректно настроен](../../../user_guide/backup.md) 
  Restic в `project_config.toml`
- Тесты проверяют интеграцию с реальным **Restic**
- Могут быть легко интегрированы в CI/CD pipeline
