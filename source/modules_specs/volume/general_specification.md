# Документация модуля `volume`

## Основное назначение

Модуль `volume` отвечает за управление виртуальными дисками (томами) в системе виртуализации. Он реализует полную цепочку — от REST API до физического создания `qcow2`/`raw`-файлов на хранилищах через `qemu-img`.

---

## Функциональность

- Создание, удаление, расширение томов
- Редактирование метаданных
- Привязка / отвязка томов к виртуальным машинам
- Мониторинг актуального состояния томов
- Валидация входных данных и проверка ограничений
- Поддержка NFS и LocalFS хранилищ

---

## Архитектура

Модуль построен на основе DDD и многослойной архитектуры:

```md
API → Service Layer → Domain Layer → Infrastructure (ORM, Storage)
```

### Слои

- **API** — FastAPI эндпоинты, валидация данных, маршрутизация.
- **Service Layer** — бизнес-логика, проверка статуса и параметров, взаимодействие с другими модулями.
- **Domain Layer** — работа с физическими томами (создание, удаление, расширение).
- **Infrastructure** — ORM, RPC, сериализация, взаимодействие с RabbitMQ.

## Эндпоинты API

| Метод | URL                                     | Описание |
|-------|-----------------------------------------|----------|
| `GET` | `/volumes/`                             | Получение списка томов, поддерживает фильтры и пагинацию |
| `GET` | `/volumes/{volume_id}/`                 | Получение информации по одному тому |
| `POST`| `/volumes/create/`                      | Создание нового тома |
| `PUT` | `/volumes/{volume_id}/edit/`            | Редактирование имени, описания, read-only |
| `POST`| `/volumes/{volume_id}/extend/`          | Расширение размера тома |
| `DELETE` | `/volumes/{volume_id}/`              | Удаление тома |
| `POST`| `/volumes/{volume_id}/attach/`          | Привязка к виртуальной машине *(Не используется. До перевода на rpc использовался для межмодульного взаимодействия)* |
| `DELETE` | `/volumes/{volume_id}/detach/`       | Отвязка от виртуальной машины *(Не используется. До перевода на rpc использовался для межмодульного взаимодействия)* |

### Подробности по эндпоинтам

#### `GET /volumes/`

- Поддерживает параметры:
  - `storage_id`: UUID хранилища
  - `free_volumes`: bool (только свободные)
  - `page`, `size`: для пагинации
- Возвращает: список томов + метаданные пагинации

#### `GET /volumes/{id}/`

- Возвращает информацию о томе по UUID
- При ошибке: 500, если не найден

#### `POST /volumes/create/`

- Требует поля: `name`, `storage_id`, `format`, `size`, `description`
- Производит валидацию имени, формата, размера, существования хранилища
- Запускает RPC-процесс создания тома в домене

#### `PUT /volumes/{id}/edit/`

- Разрешает изменение: имени, описания, флага `read_only`
- Только если том в статусе `available`
- Проверяет уникальность имени в пределах хранилища

#### `POST /volumes/{id}/extend/`

- Изменяет размер тома
- Проверки:
  - Новый размер больше текущего
  - Статус тома — `available`
  - Проверка хранилища на свободное место
  - VM, если есть, должны быть выключены

#### `DELETE /volumes/{id}/`

- Удаляет том (в БД и на диске)
- Запускается только если статус `available` или `error`
- Если том привязан к VM — ошибка

#### `POST /volumes/{id}/attach/`, `DELETE /{id}/detach/`

- Пока не реализованы в тестах и не используются
- Работа с таблицей привязок `volume_attach_vm`
- Требуют проверки состояния VM и статуса тома

## RPC

Используется двухуровневый RPC:

- `API → Service Layer` — через очередь `volume-service-layer`
- `Service Layer → Domain Layer` — через очередь `volume-domain-layer`

Обрабатываются команды: `create`, `delete`, `extend`, `attach_volume_info`

---

## Статусы тома (`VolumeStatus`)

- `new`
- `creating`
- `available`
- `extending`
- `deleting`
- `error`

---

## Хранилища

Том создается на базе `Storage`, получаемого через RPC от модуля `storage`.

Типы:

- `nfs`
- `localfs`

Параметры `mount_point` и `available_space` извлекаются для проверки условий создания и расширения.

---

## Валидации и исключения

- Все валидации в сервисном слое
- Используются исключения из `service_layer/exceptions.py`
- При возникновении ошибки — статус `error` и подробность в `volume.information`

---

## Мониторинг

Фоновая задача `monitoring()`:

- Запускается каждые 10 секунд
- Обновляет статус, размер, used-space
- Использует `qemu-img info`

---

## События

Все значимые события сохраняются в модуле `event_store` через `EventCrud`.

Примеры:

- Успешное создание
- Ошибка при RPC
- Удаление / расширение
