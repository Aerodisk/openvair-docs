# Тесты модуля `template`

> В текущей реализации тесты запускаются вручную после внесения изменений. В дальнейшем подход может быть масштабирован и интегрирован в CI/CD процессы.

## Цели тестов

- Проверка корректной работы публичных API-эндпоинтов модуля `template`.
- Обеспечение соответствия бизнес-логике управления шаблонами томов.
- Выявление и предотвращение регрессий после изменений в коде.
- Документирование допустимого и ошибочного поведения.
- Проверка граничных сценариев (валидация, авторизация, статусы, ошибки БД и RPC).
- Обеспечение безопасного рефакторинга и развития функционала.

---

## Подход к тестированию

Тесты построены как **интеграционные**:

- Используется прямое взаимодействие с API через `TestClient`.
- Тесты имитируют реальные RPC-вызовы (`RabbitMQ`) и операции с БД.
- Покрываются сценарии, максимально приближённые к работе в продуктиве:  
  - операции создания, редактирования, удаления, получения шаблонов;
  - работа с реальными тестовыми storage и volumes;
  - проверки прав доступа, ошибок, некорректных UUID, валидаций по длине и формату.
- В тестах учитываются как позитивные (успех), так и негативные кейсы (валидация, права, отсутствие ресурсов, ошибки статусов).

Покрытие:

- Все основные CRUD-операции.
- Ошибки аутентификации/авторизации.
- Валидация обязательных и опциональных полей.
- Защита от дубликатов, попыток удаления несуществующего или уже удалённого шаблона.
- Проверка асинхронных статусов (`creating`, `deleting`).
- Проверка пагинации и параметров запроса.
- Поведение при ошибках RPC и БД.

## Инфраструктура

- `pytest` — основной фреймворк для тестирования.
- `fastapi.testclient` — для интеграционного тестирования API.
- `pydantic` — для генерации входных данных.
- `uuid`, `sqlalchemy`, стандартные библиотеки для управления идентификаторами и БД.
- Конфигурация через `.env.test` и pydantic-модели.
- Логгирование через общий логгер проекта.
- Все данные очищаются после тестов (фикстуры).

## Структура файлов

```text
tests/
│
├── api/
│   ├── test_create.py     # Тесты POST /templates/
│   ├── test_delete.py     # Тесты DELETE /templates/{id}
│   ├── test_edit.py       # Тесты PATCH /templates/{id}
│   ├── test_retrive.py    # Тесты GET /templates/ и /templates/{id}
│
├── conftest.py            # Общие фикстуры и подготовка окружения (storage, volume, template, client)
├── config.py              # Конфигурация тестовой среды
├── .env.test              # Переменные среды для тестов
├── pytest.ini             # Порядок запуска и логирование
```

---

## Фикстуры

- **client**: FastAPI TestClient с настройками тестового приложения.
- **unauthorized_client**: TestClient без подмены авторизации — для негативных сценариев.
- **mock_auth_dependency**: подмена реальной JWT-аутентификации для ускорения тестов.
- **configure_pagination**: подключение поддержки пагинации FastAPI.
- **storage**: создание и удаление временного хранилища storage для шаблонов.
- **volume**: создание и удаление тестового тома.
- **template**: создание и удаление тестового шаблона.
- **cleanup_all_volumes / cleanup_all_templates**: удаление всех томов и шаблонов после тестов.

## Покрытие эндпоинтов

| Эндпоинт                           | Назначение                                  | Статус   |
|------------------------------------|----------------------------------------------|----------|
| `POST /templates/`                 | Создание шаблона                            | ✅ покрыт |
| `GET /templates/`                  | Получение списка шаблонов (с пагинацией)     | ✅ покрыт |
| `GET /templates/{template_id}`     | Получение шаблона по ID                      | ✅ покрыт |
| `PATCH /templates/{template_id}`   | Изменение имени и описания шаблона           | ✅ покрыт |
| `DELETE /templates/{template_id}`  | Удаление шаблона по ID                       | ✅ покрыт |

## Запуск тестов

```bash
cd openvair/modules/template/tests/
pytest -v
```

- Для управления выводом и порядком запуска настрой `pytest.ini`.
- Для удобства работы рекомендуется использовать плагины/интеграцию pytest в IDE (PyCharm, VSCode).

---

## Примечания

- Все тесты используют `TestClient` и реальные RPC-вызовы (RabbitMQ).
- Перед запуском тестов требуется подготовленное окружение: PostgreSQL, RabbitMQ, директории для шаблонов/томов.
- Используется тестовое хранилище (storage), которое создаётся и удаляется перед/после тестов.
- Каждый тест изолирован, порядок выполнения не влияет на результат.
- Тесты покрывают все обязательные, позитивные и негативные кейсы: права доступа, ошибки валидации, поведение при удалённых/несуществующих ресурсах, асинхронность (ожидание исчезновения/изменения статуса через wait).
- При необходимости можно быстро масштабировать покрытие и интегрировать в CI/CD pipeline.
